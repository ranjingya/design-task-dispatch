# 工作看板

看板使用飞书多维表格公式与仪表盘组件实时计算，分为需求任务管理和跨来源工作总览。

## 看板范围

- 「需求表数据统计」文件夹中的「月度工作量与及时性」展示需求任务表的任务指标、负责人任务数、ABC 构成、任务状态、按期完成率、任务明细和成员月负载分。成员月负载分来自需求任务表的月度汇总。
- 最外层「工作总览」展示四类工作占比和各类交付及时性，支持月份、人员、工作类别和创意图来源筛选。创意图来源可选京东或拼多多，只作用于创意图数据。
- 部门优化需求、2026-新品数据包暂不接入工作总览。

## 月份与人员

月份格式为 `YYYY-MM`，支持单月、连续多月和跨年多月累计。两张看板各自使用顶部月份筛选。

工作总览的「工作类别」和「创意图来源」使用平铺多选按钮，默认全选，点击按钮可勾选或取消对应选项。月份使用多选下拉框。

| 来源表 | 月份依据 | 隐藏月份字段 | 负责人 |
| --- | --- | --- | --- |
| 需求任务表 | 提交时间 | 提交月份 | 最终负责人 |
| 京东创意图 | 记录新增时间 | 统计月份 | 负责人映射到成员负荷表人员 |
| 拼多多创意图 | 截止时间 | 统计月份 | 负责人 (人员 ) 映射到成员负荷表人员 |
| 杭州优化需求 | 记录创建时间 | 统计月份 | 负责人 |
| 2027-新品数据包 | 提交时间，字段类型为记录创建时间 | 统计月份 | 负责人映射到成员负荷表人员 |

杭州优化需求和 2027-新品数据包按当前表记录创建时间统计，迁移记录归属当前表的创建月份，此口径由美工确认。京东使用独立日期字段「记录新增时间」。月份依据为空的记录没有可归属月份，保留在未限定月份的总量中。

成员月度负荷表使用「月份」文本列，分数按需求任务的提交月份和最终负责人汇总，包含已完成与未完成任务。

人员筛选名单来自成员负荷表。多人任务在每位成员的个人统计中各计一次，全员任务数量按源记录计一次。

## 四类工作占比

按有效任务数量计算，包含未完成任务。一条源记录计一个任务，空白占位记录不计入。

| 类别 | 来源表 |
| --- | --- |
| 部门需求 | 需求任务表 |
| 创意图 | 京东创意图、拼多多创意图 |
| 优化需求 | 杭州优化需求 |
| 数据包 | 2027-新品数据包 |

需求任务表中已取消或已关联京东创意图的记录不计入工作总览的部门需求，关联的创意图按创意图来源记录统计。需求任务专属看板统计其自身任务。

有效记录以任务名称、品名或货号品名非空为准。杭州优化需求中的「上新」和「优化」都归入优化需求。没有记录的类别数量为 0，饼图仅展示有数据的类别。

## 交付及时性

任务的月份归属使用上表中的月份依据；交付及时性按完成日期与截止日期比较。例如拼多多任务截止在 10 月、11 月完成，计入 10 月并判定为逾期完成。

| 分类 | 条件 |
| --- | --- |
| 提前完成 | 完成日期早于截止日期 |
| 当天完成 | 完成日期与截止日期相同 |
| 逾期完成 | 完成日期晚于截止日期 |
| 逾期未完成 | 截止日期早于今天，完成日期为空 |

已取消、未设截止日期及尚未到期的未完成任务不参与交付分布。

工作总览分别展示部门需求、拼多多创意图和 2027-新品数据包的交付及时性。需求任务使用「截止时间」「实际完成时间」，拼多多使用「截止时间」「完成时间」，2027 数据包使用「截止日期」「完成日期」。

需求任务专属看板的按期完成率，分母为所选提交月份内、截至昨日到期、未取消且已有最终负责人的任务，分子为其中提前或当天完成的任务。

### 数据接入待完善项

- 京东创意图、杭州优化需求缺少截止日期字段，暂不纳入交付及时性统计；任务数量仍纳入四类工作占比。
- 接入这两类来源的交付及时性前，需要明确截止日期字段并补齐有效日期，再与各自的完成日期比较。

## 自动计算字段

「统计工作类别」生成来源分类；月份辅助字段根据对应日期生成月份。京东创意图和 2027 数据包的「统计负责人」根据成员负荷表人员昵称映射负责人，拼多多根据人员身份筛选成员负荷表中的美工。

京东、拼多多的「统计创意图来源」供来源筛选使用；拼多多、2027 数据包的「交付及时性」生成交付分类。统计辅助字段在日常视图中隐藏，业务人员维护原有负责人、截止日期和完成日期，飞书自动更新图表。

服务器的评级、推荐和当前负载计算按各自配置运行。
